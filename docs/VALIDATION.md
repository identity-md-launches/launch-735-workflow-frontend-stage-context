# Worker validation — Genesis Protocol

This is the worker's own validation record, not an independent security audit or publication certification. Source and static export are delivered together. No deployment, publishing, private key, real wallet signature or live transaction was performed.

## Scope and assumptions

The supplied workflow calls for the GENESIS dashboard, live supply/balance/pool metrics and explorer links. The assignment additionally requires wallet recovery, swap controls, primary token actions and an attested export. All three token writes (`transfer`, `approve`, `transferFrom`) have controls. The app uses the exact Sepolia GENESIS/native-ETH pool key from the handoff, including fee 12500, tick spacing 60 and the nonzero guard. Earlier admission fee 3000 is not the trading fee.

Circulating supply cannot be verified from this handoff: no allocation/distributor addresses or a metric definition were provided. It is shown as unavailable with methodology, rather than equated to total supply. USD pricing is also unavailable. Current-tick pool liquidity is shown in raw units and is not claimed to be TVL. The supplied launch includes neither LP custody nor a liquidity-management requirement, so no LP action is invented.

The immutable configuration is loaded from `dist/imd-deployment.json`; its ABI is loaded and canonical-Keccak checked in the browser. `web/scripts/export.mjs` independently compares the source ABI with the exact pinned Git commit and handoff hash, then inventories every export file except the manifest. It also compares preserved handoff/network records with the supplied worker inputs when they exist.

## Interaction coverage

The browser suite verifies disconnected gating, exact runtime configuration/ABI loads, balance reads, wrong-chain gating, 4902 → add supplied chain → switch again, invalid decimal/slippage inputs, exact quote pool key, and native-value routing. It holds wallet signing open to verify duplicate-action locks, rejects a request then retries, confirms a native buy, confirms both separate sell approval steps followed by a no-value sell, and verifies a simulated revert never calls `eth_sendTransaction`.

It advances time to expire a quote and changes the form to invalidate one; exercises quote reverts, invalid addresses, exact transfer review/calldata, zero-reset allowance revocation, insufficient owner allowance and `transferFrom`; then disconnects the account and checks that balances/action readiness clear. It rejects tampered ABI JSON and missing contract code, and confirms a wrong-chain RPC cannot enable transactions. Missing-wallet guidance, keyboard-only quoting, contrast and resource integrity are included.

All wallet sends in these tests terminate in the mock provider. This is not proof of actual wallet-extension UX or funded transaction settlement. Transaction cancellation/replacement and timeout handling were reviewed in source but not reproduced with a live replacement transaction.

## Read-only reproduction

Run `node web/scripts/live-check.mjs 11851614`. The script reads endpoints and addresses only from the generated runtime manifest. It makes `eth_chainId`, `eth_getCode` at the pinned block, token `eth_call`s, StateView `getSlot0(poolId)` / `getLiquidity(poolId)`, and a Quoter `quoteExactInputSingle` simulation for `1000000000000000` wei (0.001 ETH), zeroForOne true, exact handoff pool key and empty hook data. Output at the recorded block: `49154311933419319380391` base units GENESIS, estimated gas `87366`. No `eth_sendTransaction` is used by that script. See its source for exact ABI-encoded requests; archive availability may change.

The router encoding follows the supplied pinned workflow; it was cross-checked against the [official Uniswap swap guide](https://developers.uniswap.org/docs/protocols/v4/guides/swapping/swapping). Addresses are exclusively from the network handoff, not documentation examples.

## Completion and limitations

Source, export and worker validation are complete. Repository commit creation is blocked by the sandbox; the worker must collect the allowed worktree outputs. The following requirement limitations remain:

- The actual repository `.git` directory is read-only; staging and committing failed with `Unable to create .git/index.lock: Read-only file system`. No repository commit was created. A separate complete working-tree snapshot in authorized scratch space produced a 1,530,477-byte Git bundle (below 8 MiB); it is a size check, not a substitute for the publisher's repository commit. Its tree was 3,066,278 uncompressed bytes, including the original tracked contract/library files. The original partial-clone history could not be repacked within the read-only repository.
- Root `DESIGN.md` is outside the explicit write budget. The implemented design document is delivered at `docs/DESIGN.md`; no out-of-scope root file was created.
- A reliable circulating-supply number cannot be delivered without a definition and verified allocation data. The page states this limitation openly.
- No real wallet approval/swap/transfer, live transaction replacement, physical device, screen reader or native browser zoom session was performed. Browser mock receipts do not establish real-chain settlement behavior.
- No site URL/CID or absolute social preview image is claimed. Publication and post-publication configuration/RPC checks happen later in the control plane.

Git scope, complete working-tree snapshot bundle bytes and static manifest checks are recorded in `evidence/submission.json`. Protected Solidity, Foundry, library and root configuration files are preserved.
